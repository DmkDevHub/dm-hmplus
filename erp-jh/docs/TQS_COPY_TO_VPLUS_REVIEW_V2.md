# TQS 테이블 vplus 복사 검토 (JH TQSA→TQSB, TQSB→TQSC)

> 작성일: 2026-11-13 · 범위: **DB 간 비교만**(JH `JH202610` ↔ vplus `VPLUS202611A`, 192.168.1.25:1521:ORCLU) · 데이터 딕셔너리 조회만 했고 DB는 바꾸지 않았다.

## 0. 결론

**이 이름 규칙이면 이름 충돌이 없다.** 앞 검토의 이름 충돌 8쌍 문제는 이 규칙으로 해결된다. 남은 것은 이름이 아니라 복사 방법에 관한 주의사항이다(5장).

| 검사 | 결과 |
|---|---|
| 바꾼 테이블 이름끼리 중복 | 없음 |
| 바꾼 테이블 이름이 vplus 기존 객체와 겹침 | 없음 |
| 바꾼 PK·FK·인덱스 이름끼리 중복 | 없음 |
| 바꾼 PK·FK·인덱스 이름이 vplus 기존 이름과 겹침 | 없음 |
| 이름 길이 128자 초과 | 없음 |
| vplus에 `TQSB`·`TQSC` 이름의 객체·제약조건 | 없음 |

## 1. 이름 규칙

| JH | vplus | 개수 |
|---|---|---:|
| `TQSA_*` | `TQSB_*` | 94 |
| `TQSB_*` | `TQSC_*` | 14 |
| 합계 | | 108 |

- 테이블뿐 아니라 PK·FK·인덱스 이름 안의 `TQSA`/`TQSB`도 같은 규칙으로 바꾼다.
- **두 치환은 한 번에 해야 한다.** `TQSA→TQSB`를 먼저 하고 `TQSB→TQSC`를 나중에 하면, 방금 TQSB로 바꾼 이름이 다시 TQSC가 된다.
- vplus의 기존 `TQSA_*` 테이블 83개는 건드리지 않는다.

## 2. 앞 검토의 충돌 8쌍

앞 검토에서 막혔던 8쌍은 다음처럼 서로 다른 이름이 된다.

## 3. 제약조건·인덱스 이름

- 이름을 직접 붙인 PK 95개, FK 31개, PK가 아닌 인덱스 0개를 검사했다. 바꾼 뒤 서로 겹치지 않고, vplus 기존 이름과도 겹치지 않는다.
- 참고로 이름을 바꾸지 않고 그대로 쓰면 82개가 vplus 기존 이름과 겹친다(`PK_TQSA_APRV` 등). 그래서 제약조건·인덱스 이름도 반드시 함께 바꿔야 한다.
- NOT NULL 제약 226개는 시스템 이름(`SYS_C...`)이라 새로 만들 때 새 이름이 자동으로 붙는다.
- CLOB 컬럼 3개의 LOB 인덱스는 테이블을 만들 때 자동으로 생긴다.

테이블 이름과 맞지 않는 PK 이름(바꾼 뒤 기준). 그대로 둬도 동작에는 문제가 없다.

## 6. 프로시저 (참고, 이번 복사 범위 밖)

- **테이블만 복사하면 vplus의 기존 프로시저에는 영향이 없다.** vplus에서 TQS 테이블을 참조하는 프로시저 213개는 기존 `TQSA_*`만 참조한다.
- 나중에 JH 프로시저 274개를 옮길 때는 아래를 주의해야 한다.
  - 프로시저 안의 테이블 이름도 같은 규칙(`TQSA→TQSB`, `TQSB→TQSC`)으로 **한 번에** 바꿔야 한다.
  - TQSA와 TQSB를 함께 참조하는 프로시저가 23개다. 한 번에 바꾸면 문제없지만, 순서대로 바꾸면 잘못된다.
  - JH 프로시저 중 190개는 vplus에 **같은 이름의 객체가 이미 있다**. 그대로 만들면 vplus 프로시저를 덮어쓴다. 프로시저 이름도 바꿀지 정해야 한다.

## 7. 결정이 필요한 사항

1. 실제 부모와 맞지 않게 되는 FK 이름과, 테이블 이름과 맞지 않는 PK 이름을 정리할지(3·4장).
2. 개인정보 컬럼 값을 그대로 복사할지(5장).
3. 데이터까지 복사할지, 구조만 만들지.
