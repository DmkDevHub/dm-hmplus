# JH → vplus 공통코드 복사 계획 (QS → QH)

> 작성일: 2026-11-13 · 원본: JH `JH202610` · 대상: vplus `VPLUS202611A` (192.168.1.25:1521:ORCLU)
> 관련: [QH_MIGRATION_RESULT.md](QH_MIGRATION_RESULT.md)(QH 객체 이관 결과)
> 1~8장의 수치는 실행 전에 두 DB를 조회해서 확인한 값이다.
> **실행 완료(2026-11-13 15:22): 1,032행을 넣었고 검증을 마쳤다. 결과는 9장에 있다.**

## 1. 목적

JH에서 아래 쿼리로 조회한 공통코드를 **코드 값의 `QS`를 `QH`로 바꿔** vplus `TCOA_COMCODE`에 넣는다(2026-11-13 결정).

```sql
SELECT *
FROM TCOA_COMCODE
WHERE HRNK_CD LIKE 'QS%'
ORDER BY HRNK_CD, COM_CD
```

- 예: `QS073`/`QS` → `QH073`/`QH`, `QS0730101`/`QS07301` → `QH0730101`/`QH07301`, `1`/`QS024` → `1`/`QH024`
- vplus에는 최상위 코드 `QH`(`HRNK_CD='*'`, 이름 `(신)안전`)가 이미 있고, 그 아래 코드는 비어 있다. 이번 작업으로 이 `QH` 아래에 코드 체계가 들어간다.

## 2. 원칙

- **이 작업은 vplus의 기존 테이블(`TCOA_COMCODE`)에 행을 넣는다.** QH 이관의 0장 원칙("기존 테이블에 INSERT하지 않는다")에 대한 **사용자 지시에 따른 예외**다.
- 예외 범위
  - 새 키(`QH` 계열)만 INSERT한다. 바꾼 키 1,032개는 vplus의 기존 키와 하나도 겹치지 않는다(확인함).
  - **vplus에 같은 키(`COM_CD`, `HRNK_CD`)가 있으면 덮어쓰지 않고 오류로 멈춘다**(2026-11-13 결정).
    - `MERGE`나 `UPDATE`는 쓰지 않고 `INSERT`만 쓴다. 같은 키가 있으면 `ORA-00001`(PK 중복)이 난다.
    - 실행 직전에 키 중복을 먼저 검사한다. 1건이라도 있으면 INSERT를 시작하지 않고, 겹치는 키 목록을 오류로 보고한다.
    - INSERT 도중 오류가 나면 전체를 롤백한다. 일부만 들어간 상태로 남기지 않는다.
  - vplus의 기존 행은 `UPDATE`/`DELETE`하지 않는다. vplus에 이미 있는 **QS 코드 776행도 그대로 둔다.**
  - 테이블 구조, 제약조건, 인덱스는 바꾸지 않는다.
- JH는 조회만 한다.
- 되돌리기는 이번에 넣은 키만 지운다.

## 3. 변환 규칙

| 컬럼 | 규칙 | 대상 행 |
|---|---|---:|
| `HRNK_CD` | 맨 앞의 `QS`를 `QH`로 바꾼다 | 1,032 (전부) |
| `COM_CD` | 맨 앞이 `QS`이면 `QH`로 바꾼다. 아니면 그대로 둔다(예: `1`, `A`) | 689 |
| 예외 1행 | `QS0600101`/`QS0601` → `QH0600101`/**`QH06001`** (상위코드 입력 오류 바로잡기, 6장 결정 1) | 1 |
| 그 밖의 33개 컬럼 | 그대로(JH 값) | |

- 조회한 1,032행에서 `QS`가 들어 있는 곳은 `COM_CD`와 `HRNK_CD`의 맨 앞뿐이다. 이름(`CD_NM`)이나 특성값(`CHRC_VAL_*`)에는 `QS`가 없다(확인함).
- `QS`와 `QH`는 글자 수가 같다. 그래서 바꾼 뒤에도 가장 긴 값이 12자로, 컬럼 길이(20자) 안이다.

## 5. 영향: QH 객체와 데이터가 쓰는 코드 값

공통코드를 `QH`로 넣어도, **이미 이관한 QH 프로시저·함수와 복사한 데이터는 아직 `QS` 코드 값을 쓴다.** 코드 이름을 찾는 곳에서 새 `QH` 코드와 맞지 않는다.

| 위치 | 내용 | 규모 |
|---|---|---|
| QH 프로시저·함수 소스 | 문자열로 쓴 QS 코드 값. 예: `FHRZ_GETCDNAME(x, 'QS031')` | 코드 값 51개, 233곳, 객체 80개 |
| `TQHA_CKLST` | `COM_CD`(3종), `HO_CHK_DIV_CD2`(13종) | 118행 |
| `TQHA_CKLST_ITM` | `COM_CD`(3종), `HO_CHK_DIV_CD2`(13종) | 395행 |

- 소스의 QS 코드 값 51개 중 48개는 이번에 넣는 코드에 들어 있다. 나머지 3개(`QSZ14`, `QSZ1410`, `QSZ1490`)는 JH 공통코드에도 없다.
- 지금 상태로 두면 위 소스와 데이터는 vplus에 원래 있던 **QS 코드 776행**을 계속 본다. 그중 일부 코드만 있어서 코드 이름이 안 나오는 곳이 생긴다.
- 맞추려면 별도 작업이 필요하다. **이번에는 하지 않고 보류한다**(6장 결정 3). 대상은 모두 이번 이관으로 만든 객체와 테이블이라 vplus 기존 객체는 바뀌지 않는다.
  - QH 소스의 코드 문자열 `'QS…'` → `'QH…'`: 객체를 다시 만들어야 한다.
  - `TQHA_CKLST`, `TQHA_CKLST_ITM`의 코드 컬럼 값 `QS…` → `QH…`: `UPDATE`가 필요하다.

## 7. 진행 단계

산출물 위치: `erp-jh/scripts/comcode_qh/`. 단계마다 결과를 보고하고 승인을 받는다.

1. **기준선 저장(조회)**: vplus `TCOA_COMCODE` 전체 행 수와, `QS`/`QH`로 시작하는 행 전체를 파일로 저장한다.
2. **SQL 생성(조회, 검토용)**
   - `mapping.csv`: JH 키와 바꾼 키(1,032행)
   - `10_insert.sql`: INSERT 문 1,032행(`QH0600101`은 상위코드를 `QH06001`로 바로잡음)
   - `99_rollback.sql`: 넣은 키만 지운다(`DELETE ... WHERE COM_CD=:1 AND HRNK_CD=:2`)
   - 검사
     - 바꾼 키가 vplus에 없는지
     - 모든 상위코드가 있는지
     - `QS` 문자가 남지 않았는지
     - `COM_CD`·`HRNK_CD` 말고는 JH 값과 같은지
3. **INSERT 실행(vplus에 쓰기)**
   1. 넣을 키 1,032개가 vplus에 있는지 검사한다. **1건이라도 있으면 오류로 멈추고 겹치는 키를 보고한다**(덮어쓰지 않음).
   2. 한 트랜잭션으로 `INSERT`만 실행한다(`MERGE`/`UPDATE` 없음).
   3. 도중에 오류(예: `ORA-00001` PK 중복)가 나면 전체를 롤백하고, 오류와 해당 키를 보고한다.
   4. 오류가 없으면 커밋한다.
4. **검증(조회)**
   - 넣은 행이 규칙대로 바뀌었는지(JH 값과 1:1 비교)
   - vplus 전체 행 수가 기준선 + 넣은 행 수인지
   - 기존 행(기존 QS 776행 포함)이 기준선과 같은지
5. **결과 보고**: 이 문서에 결과를 덧붙인다.
6. QH 소스의 코드 문자열과 데이터 코드 값 맞추기는 보류한다(결정 3). 나중에 따로 계획한다.
