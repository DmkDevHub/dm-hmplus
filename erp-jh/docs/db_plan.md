# Oracle DB 테이블 복제 사전 분석 및 실행 계획서 작성 요청

## 목적
DB B의 TQSA/TQSB 테이블을 DB A로 복제하기 전에 실제 DB 환경을 분석하고 상세 실행 계획서를 먼저 작성한다.

현재 작업은 사전 분석 및 문서 작성만 수행한다.

**실제 테이블 복사 및 DB 변경은 절대 수행하지 않는다.**

## 1. 복제 대상
- 원본: DB JH
- 대상: DB vplus
- 테이블명에 TQSA 또는 TQSB가 포함된 테이블만 대상
- TQSA가 포함된 테이블명은 TQSB로 변경
- 기존 TQSB 테이블명은 그대로 유지
- 컬럼명은 원본 유지
- 실제 데이터는 복사하지 않음

## 2. 복제 범위
- 테이블 및 컬럼 전체 구조
- 데이터 타입, 길이, 정밀도, NULL, DEFAULT
- PRIMARY KEY
- FOREIGN KEY
- UNIQUE 제약조건
- CHECK 제약조건
- INDEX
- 테이블 및 컬럼 COMMENT

제약조건명과 인덱스명에 TQSA가 포함된 경우 TQSB로 변경하는 방안을 검토한다.

## 3. 사전 분석 작업

### 3.1 DB 환경 분석
- 두 DB의 Oracle 버전 확인
- 원본 및 대상 스키마 확인
- 메타데이터 조회 권한 확인
- DB A의 객체 생성 권한 확인 (권한 변경 금지)

### 3.2 원본 테이블 분석
- DB B에서 복제 대상 테이블 전체 조회
- 테이블별 컬럼 구조 확인
- PK, FK, UK, CHECK 확인
- 인덱스 구성 확인
- COMMENT 확인
- FK 참조 관계 및 외부 의존성 분석

### 3.3 대상 DB 분석
- DB A에 이미 존재하는 대상 테이블 확인
- 테이블명 변환 후 중복 여부 확인
- 제약조건 및 인덱스 이름 충돌 확인
- FK 참조 대상 존재 여부 확인
- 복제 가능한 테이블과 추가 검토가 필요한 테이블 분류

## 4. 실행 방법 설계

실제 복제 시 사용할 방법을 분석하고 다음 내용을 문서화한다.

1. Oracle DBMS_METADATA를 활용한 DDL 추출 방법
2. TQSA → TQSB 이름 변환 방법
3. 테이블 생성 순서
4. PK, UK, CHECK 생성 순서
5. 인덱스 생성 순서
6. FK 생성 순서
7. COMMENT 적용 방법
8. 객체명 충돌 처리 방법
9. 실패 시 중단 및 복구 방법
10. 복제 완료 후 검증 방법

DDL 생성 시 원본 객체의 테이블명뿐 아니라 관련 제약조건명, 인덱스명, FK 참조명 등을 정확하게 변환하는 방법을 검토한다.

## 6. 절대 금지 사항
- CREATE, ALTER, DROP, TRUNCATE 실행 금지
- INSERT, UPDATE, DELETE, MERGE 실행 금지
- DB A와 DB B의 기존 객체 수정 금지
- 기존 프로젝트 소스코드 수정 금지
- 임의로 테이블명이나 컬럼명 변경 금지
- 사용자 승인 없이 복제 작업 진행 금지

## 7. 최종 지시

현재는 사전 분석과 실행 계획서 작성까지만 수행한다.

분석에 필요한 SELECT 및 메타데이터 조회만 허용한다.

실제 복제 SQL은 실행하지 않는다.

`TQS_DB_MIGRATION_PLAN.md` 문서 작성이 완료되면 주요 내용을 요약하여 보고하고 사용자 검토 및 승인을 기다린다.

문서 승인 이후에도 별도의 명시적 실행 지시가 있기 전까지 DB 변경 작업을 수행하지 않는다.
