# 프로젝트 이식 작업 규칙

## 기본 원칙
- 프로젝트 1은 이식 대상이다.
- 프로젝트 2는 참조용이며 절대 수정하지 않는다.
- 사용자가 명시적으로 지정한 작업만 수행한다.
- 사용자가 지정하지 않은 파일, 코드, DB 객체는 수정하지 않는다.
- AI는 이식 작업의 범위를 스스로 확장하지 않는다.

## 수정 절차
1. 사용자가 수정 대상과 작업 내용을 지정한다.
2. AI는 지정된 대상과 직접적인 의존성 및 충돌 가능성을 분석한다.
3. 추가 수정이 필요하면 해당 파일과 이유만 보고한다.
4. 사용자가 승인하지 않은 추가 수정은 수행하지 않는다.
5. 승인된 대상에 한해서만 수정한다.
6. 변경 후 실제 수정 파일 목록, 변경 내역, 검증 결과를 보고한다.
7. 다음 사용자 지시가 있을 때까지 추가 수정하지 않는다.

## 금지사항
- 전체 프로젝트 일괄 변경
- 임의 리팩토링
- 임의 파일명 변경
- 공통 모듈 자동 수정
- 승인되지 않은 DB DDL/DML 실행
- 임의 의존성 추가 및 설정 변경
- Git 자동 커밋 및 Push
- 사용자 지시 없이 다음 단계 진행

## 작업 완료 보고
- 요청한 작업
- 실제 수정한 파일
- 변경한 내용
- 검증한 항목 및 결과
- 추가 수정이 필요한 파일과 사유
- 미해결 사항

수정 범위 밖에서 문제가 발견되면 수정하지 말고 사용자에게 보고한다.
