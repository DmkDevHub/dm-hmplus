기본 흐름 — 조회하고 고치기

① 화면 열기
접수기간 = 올해 1월 1일 ~ 오늘. 지난번 현장·동이 기억돼 있으면 자동 조회
→
② 현장 선택
동 목록을 불러와 첫 동을 고른 뒤 바로 조회
→
③ 목록에서 선택
상세와 사진상태를 서버에서 읽어 옴
→
④ 수정 후 [저장]
필수값 검사 → 저장 → 그 줄만 다시 읽어 반영

신규 접수

① [+추가]
상세가 빈 신규 폼으로 바뀌고 머리에 「신규작성」 표시
→
② 자동 채움
접수일자 = 오늘, 접수구분 = 수시점검, 접수단계 = A/S관리
→
③ 동 · 호 선택
호를 고르면 요청자·연락처·비고가 세대정보에서 채워짐
→
④ 공간 · 부위 선택
협력업체가 비어 있고 매칭 후보가 1건이면 협력업체·공종·하자유형 자동 채움
→
⑤ [저장]
서버가 접수순번 부여 → 목록 다시 조회 후 새 줄 선택
[세대복사]는 지금 고른 접수건의 동·호·요청자·연락처를 복사해 신규 폼을 연다. 같은 세대에 여러 건을 접수할 때 쓴다.

5조회조건

항목입력 방식규칙
현장 필수csSiteCd / csSiteNm현장 찾기(코드 + 이름)다음에 열 때 기억해 둠. 바꾸면 다른 조건을 비우고 동 목록 새로 불러와 자동 조회
접수기간acpStrDt ~ acpEndDt기간 선택처음엔 올해 1월 1일 ~ 오늘. 시작이 종료보다 늦으면 자동 보정. 현장을 바꾸면 시작일은 비우고 종료일은 오늘
동/호searchBl / searchRm동 콤보 + 호 입력동 목록은 현장 기준. 첫 동이 자동 선택됨. 호는 포함 검색(LIKE)
완료searchSucYn전체 / 예 / 아니오예 = 완료일자 있음 또는 임의종결
협력업체searchCustCd협력업체 찾기고르면 옆 「공종」 칸에 대·중공종명이 표시됨. 지우면 공종도 비움

조회 조건 규칙 — 현장이 없으면 「현장을 선택하세요」. 그리고 동 · 협력업체 · 진행상태 중 하나는 있어야 한다(긴급 = 예 이면 예외). 첫 자동 조회도 같은 규칙을 따른다.
조건을 바꾸면 목록과 상세를 비우고 「조회 전」 상태로 돌아간다. 저장 안 한 내용이 있으면 먼저 확인창이 뜨고, 취소하면 바꾼 조건이 원래대로 돌아간다.

13구현 시 주의

원본 화면이 실제로 겪은 문제에서 나온 규칙이다. 새로 만들 때 같은 실수를 피하기 위한 목록.

  • 빈 날짜는 null 로 저장 — 빈 문자열로 저장하면 완료 여부 판정이 뒤집혀 미완료 건이 완료로 분류된다
  • 날짜 형식 — 화면은 YYYY-MM-DD, 서버는 YYYYMMDD
  • 저장 전 필드명 되돌리기 — 읽을 때 별칭(CTP_1·CTP_2·CTP_3·ASTYPE_3·CUST_CD)으로 받은 값을 DB 컬럼명(LCTP·MCTP·SCTP·AS_TP·CONT_CO_CUST_CD)으로 되돌려 보낸다. 빠뜨리면 그 컬럼이 비워진다
  • 접수순번은 숫자 — 필터 줄이나 빈 값을 서버로 보내면 변환 오류가 난다
  • 미저장 확인창 중복 금지 — 조회조건·목록 이동의 확인은 프레임워크(SearchBar guard, GridPanel guard)가 하므로 화면 코드에서 다시 묻지 않는다
  • 서버 값 반영은 변경으로 치지 않기 — 상세를 다 읽은 직후와 저장 직후 변경 기준점을 다시 잡는다. 안 하면 아무것도 안 건드렸는데 「변경된 데이터가 있습니다」가 뜬다
  • 폼 일부 값 변경은 apply 사용 — vm.set('form.X')는 신규 표시를 풀어 신규 폼이 잠긴다
  • 버튼 켜짐·잠김은 식으로 — 별도 상태 변수를 두지 않고 화면 식으로 계산한다
  • 새 창은 클릭 즉시 연다 — 비동기 처리 뒤에 열면 팝업 차단에 걸린다
  • 가려진 개인정보 값 — 삭제 요청에는 *가 든 휴대폰번호 등을 빼고 보낸다(서버 보호장치가 거부)
  • 라벨·메시지 — 화면 문구는 라벨·메시지 키로만. 이벤트는 @, 데이터는 :
