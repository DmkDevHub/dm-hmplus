# 계정별 권한 테스트 시나리오 — 화면 권한·버튼 권한

## 개요
- 목적: 시험 계정마다 화면이 열리는지(화면 권한)와 화면 안 버튼이 등급대로 열리고 닫히는지(버튼 권한)를 화면 단위로 확인
- 진행 순서·판정 구분: 같은 폴더 `계정별-권한-테스트-순서.md` 따름
- 계정별 화면 등급 근거: `products-erp-h/db/common-admin/P3-plan-role-service.tsv`(2026-11-09 부여 계획) · 시험 전 관리자 계정으로 사용자권한 관리 「실효 메뉴 권한」을 열어 실제 등급을 확인하고, 다르면 해당 화면 표의 등급을 고친 뒤 시험
- 버튼 근거
  - CS 화면: `products-erp-h/app/src/main/resources/pages/cs/<화면>.js` 의 버튼 선언(2026-11-18 소스) · 버튼 이름은 erp-h 라벨 데이터(`db/module/erp/install/common/*.sql`) 한글값
  - 공통·시스템 화면: 화면별 권한 정의표 `products-erp-h/docs/work/common-admin/dev-guide/auth-def/<화면ID>.md` 의 「열리는 버튼·칸」
- 화면 경로 근거: 공통·시스템은 작업대장 v3 · CS 는 2026-11-09 서비스 표 부모 메뉴 · 실제 위치가 다르면 화면 ID 로 찾고 비고에 기록

## 1. 판정 규칙

### 1-1 화면 권한
| 확인 | 기대 |
|---|---|
| 부여된 화면 | 왼쪽 메뉴에 표시 · 열면 조회 동작 |
| 부여되지 않은 화면 | 메뉴에 없음 · 주소창에 `http://localhost:8081/page/<화면ID>` 를 직접 입력해도 화면·데이터가 열리지 않음 |
| 부여되지 않은 화면의 API | 콘솔 `app.post` 직접 호출 시 HTTP 403 또는 권한 오류 |

### 1-2 버튼 권한
| 버튼 종류 | 요구 조건 | 근거 |
|---|---|---|
| 프리셋 추가·삭제·저장·작업저장·수정·작성·복사·엑셀 가져오기·파일 올리기·실행·잠금해제·비밀번호 초기화 | 등급 2 이상(화면에서 authLevel 을 따로 주면 그 값) | hmp `components-react.js` BUTTON_PRESETS |
| 프리셋 엑셀 내보내기·파일 내려받기·인쇄 | 등급 무관 · 실효 권한의 허가(allow_*) Y | 같은 곳 · 권한서비스 매핑의 허가 칸 |
| 일반 버튼 `authLevel="N"` | 등급 N 이상 | 화면 소스 |
| 일반 버튼(authLevel 없음) | 등급 무관 · 화면만 열리면 활성 | 화면 소스 |
| 그리드·폼 편집 | 등급 2 미만이면 자동 읽기 전용 · `:editable="false"` 그리드는 항상 읽기 전용 | 프레임워크 규칙 |
| 그리드 삭제 `:delete="app.page.authLevel >= 3"` | 등급 3 이상 | 화면 소스 |

- 등급이 모자란 버튼의 표시: 설정 `ui.auth.button.mode` 기본값 `disabled` 이면 회색 비활성으로 보임 · `hidden` 이면 숨김 · 시험 전 현재 값 확인 후 표의 「비활성」을 그 값에 맞춰 판정
- 업무 상태 조건: 등급이 충분해도 진행 상태(검토 대기·저장된 행 선택 등)가 맞지 않으면 비활성 · 표의 「업무 상태 조건」 칸을 먼저 맞춘 뒤 등급 판정
- ★ 표시: 등급 조건 없이 데이터를 바꾸거나 처리하는 업무 버튼 · 등급 1 계정에서도 활성이므로, 눌렀을 때 서버가 거절하는지 반드시 확인(3장 목록) · 처리되면 버튼 등급 누락 결함으로 기록
- 결과 칸: 표의 모든 계정 칸이 기대와 같으면 `[x]` · 다르면 비우고 비고에 계정·실제 상태 기록
